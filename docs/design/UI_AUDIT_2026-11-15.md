## Why the reference reads as trustworthy (principles adopted, not copied)

1. **The answer comes first.** Each page opens with a plain-language verdict, and the evidence follows.
2. **A persistent "at a glance" rail.** A few key figures, each with its period and comparison, stay visible.
3. **The source sits next to the claim.** Every chart has a "Queries" link to the exact query, its inputs and a CSV export.
4. **Quiet chrome.** Neutral surfaces, one accent, an icon-plus-label sidebar, and almost no decoration.

For Verac, these principles became: a dashboard that answers five questions in order; a "where this number comes from" line on every figure; Live Proof as a filterable, exportable evidence ledger; and a restrained graphite-and-teal palette.

## Problems found in the current UI

- **Palette.** The single deep-green palette tints every surface, so success-green has no contrast in dark mode, and "live" looks the same as ordinary text.
- **Uniform grids.** Every page is a stack of equally weighted `Card`s. Nothing is primary, and tables and stats look the same.
- **Dashboard.** It answers "is the chain up?" but not "how much money do we have, what needs me, what are agents doing, is anything unsafe?". The data for all of these already exists (vault snapshot, transactions, agent_tasks, threat posture).
- **Shell.** The sidebar is 27 links in one long scroll, with no collapse, no search and no command palette. The top bar shows a static string, with no organisation, no pending-approval count and no live network state.
- **Theme.** The theme toggle only switches between light and dark. You cannot choose "system".
- **Command Center.** It shows 15 near-identical cards, without grouping or a detail view.
- **Live Proof.** It's one long list of hashes, with no filtering, copying or export, and no explanation of how each verification works.
- **Quantum Simulator.** It only has an address lookup. The attack scenarios are described elsewhere, but the page doesn't link to the real refusals on Live Proof.
- **Bugs.** `var(--fg)` is used on Activity but never defined. Chips there render without a visible active border.
- **Missing states.** There is no shared skeleton, notice or copy-to-clipboard component, so each page invents its own.

## Implementation checklist (prioritised)

1. Tokens: graphite/teal dark theme, off-white/deep-teal light theme, semantic tones (live, simulation, warning, danger, info), Geist fonts.
2. Shared primitives: `Badge`, `PageHeader` (with actions and meta), `Card` (with description and flush mode), `Stat`, `Notice`, `EmptyState` (with action), `Skeleton`, `CopyButton`, `Hash`, table classes, button variants.
3. Shell: grouped, collapsible, persistent sidebar; icon-only mode with tooltips; mobile drawer; top bar with organisation, breadcrumb, live network status, pending approvals, theme menu (light/dark/system) and user menu; Ctrl/Cmd+K command palette that respects role.
4. Dashboard rebuilt around five questions, with each section streamed separately so one slow integration doesn't block the page.
5. Command Center: agents grouped by responsibility, with a detail panel showing authority, tools and real task history.
6. Live Proof: a filterable evidence ledger with expandable rows, copy buttons, CSV/JSON export and a verification-method note.
7. Quantum Simulator: step-by-step scenarios, each labelled *scenario walkthrough*, linked to on-chain evidence only where it exists.
8. Treasury, Procurement and Threats: payment flow steps, a pipeline by status, and severity ordering.
9. Every other page picks up the new system through the shared primitives.

## Rules kept

Every number on screen comes from the chain, the database or the deployment file. Simulation and live testnet are always labelled. No signing, custody, contract, API or policy logic was changed by this work.
