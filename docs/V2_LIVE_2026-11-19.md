# TreasuryVault V2 on Diana testnet: independent post-quantum approval, live (2026-11-19)

An isolated environment, sharing no key or contract with Verac's existing treasury (which was not touched).
Reproduce with `npx tsx packages/qorechain/scripts/v2-setup.ts --broadcast` and `v2-live.ts --broadcast`.
Raw records: `deployments/v2-diana.json` and `deployments/v2-live-results.json`.

## What was proven

**The application server cannot make a payment the administrators did not sign.** An attacker holding everything the
server holds (the agent's key, the relayer's key, both their registered ML-DSA-87 keys) was refused on chain every time.
Payments went through only with two of the three administrators' ML-DSA-87 signatures, which the vault verified on chain
with QoreChain's PQC Verify precompile against each administrator's registered, possession-proven key.

budget ran out first. The target restriction itself was proven on 2026-11-17 (category proof E-2).

## What an attacker with the server can still do

* Refuse service: not relay, or pause the vault (the relayer is the guardian). Pausing and revoking only reduce risk;
  resuming needs two administrators.
* Spend the agent's and relayer's own fee balances (it holds their keys and can open windows for them).
* Read and alter the website's database. That can change what an administrator is *shown*, so the administrator's
  signing tool recomputes the digest from the payment fields and shows them before signing.

## What this does not show

* The administrators' keys here are files on one computer, not separate devices. Independence in practice depends on
  each administrator keeping their own key.
* V2 is not yet wired into the website's payment flow, and has not had an external audit.
* ML-DSA-87 verification costs about 312,000 gas per signature on Diana.

## Administrator key replaced (2026-11-20)

admin-3 (`0x6A73…815d`) was replaced by a new key, admin-4 (`0x02fF…4e9f`), using the procedure in docs/RUNBOOK.md
section 2a. Each administrator signed in a separate run of `v2-admin.ts sign`; the signatures were combined only by the
relay command, which checked each against the signer's registered key before sending.

The vault went from 3 administrators to 4 and back to 3, never below its threshold of 2. The removal was signed with the
new key, which proves it works. Afterwards the old key was refused: it is no longer an administrator, and the used
requests and signatures are refused because the admin nonce has moved on. All three administrators' keys are still files
on one computer; the procedure lets each move to its own device.
